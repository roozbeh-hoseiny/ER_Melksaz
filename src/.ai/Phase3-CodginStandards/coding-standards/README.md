# Coding Standards

Version: 1.0

---

# Purpose

This folder defines the mandatory coding standards for the repository.

These documents describe **how code is written**, whereas the Architecture phase describes **how software is designed**.

Every AI-generated implementation and every manually written implementation must follow these standards.

---

# Scope

The Coding Standards define:

* Naming conventions
* File organization
* C# language usage
* .NET best practices
* Code style
* Error handling
* Dependency Injection
* Async programming
* Logging
* Configuration
* Performance
* Security
* Documentation
* Testing conventions

---

# Objectives

The objectives of these standards are:

* Improve readability.
* Improve maintainability.
* Reduce cognitive load.
* Produce predictable code.
* Enable consistent AI-generated implementations.
* Minimize unnecessary architectural discussions.

---

# Principles

Every coding decision should favour:

* Readability over cleverness.
* Explicitness over magic.
* Simplicity over abstraction.
* Consistency over personal preference.
* Maintainability over short-term convenience.

---

# AI Responsibilities

Before generating code, the AI must verify:

* Existing repository conventions.
* Existing naming patterns.
* Existing project structure.
* Existing dependency injection style.
* Existing testing style.
* Existing error handling conventions.

The AI should extend existing patterns rather than introduce new ones.

# Relationship with Other Phases

These standards extend:

* Phase 1 — AI Core
* Phase 2 — Architecture

If a coding standard conflicts with an architectural rule:

The Architecture rule always takes precedence.

---

# Guiding Principle

Architecture defines **where code belongs**.

Coding Standards define **how that code should be written**.

Together they ensure that every generated feature appears as though it was written by the same engineering team.
